# Assignment Report PDF Export

## Goal

Every time a student exports an assignment report, produce a companion PDF
next to the JSON so instructors (and students) can see the report without
reading JSON. The PDF is a presentational companion only. JSON remains the
authoritative, integrity-checked artifact and is untouched in format and hash.

## Scope

- New: `Export Assignment Report` now writes **both** `<assignment>.report.json`
  and `<assignment>.report.pdf` to the user-chosen location, with the same
  base filename.
- The JSON report (format, integrity hash, verifier CLI, dashboard) is NOT
  changed.
- No new reads from the database; PDF data comes from the in-memory report.

## Out of scope

- PDF verification of any kind (PDF carries no integrity hash; the JSON does).
- PDF for general metrics/CSV export.
- Dashboard UI changes.

## New files

- `src/reports/AssignmentPdfGenerator.ts`
  Builds a pdfmake `DocumentDefinition` from an `AssignmentReport` and renders
  the PDF to a Buffer/Uint8Array.
- `src/reports/chartSvg.ts`
  Pure helpers that render the two SVG visuals embedded in the PDF:
  - authorship trend line chart (daily AI % over the assignment window)
  - ownership/authorship gauge-style summary visuals
- Tests in `src/reports/__tests__/` alongside them.

## Data flow

1. `exportAssignmentReport` produces the report + `.json` exactly as today.
2. After JSON is written, `AssignmentPdfGenerator.generate(report)` builds
   the document definition.
3. The PDF is written to the same save path with the `.pdf` extension.
4. PDF write failure is surfaced as an error toast, but the already-written
   JSON is kept and reported as saved.

## Charts

Trend line chart data source: `metrics.rawEvents[]` (already in the report).

- Group events by local calendar day between `assignment.startDate` and
  `assignment.endDate`.
- For each day: `aiLines = sum(e.linesOfCode where e.source === 'ai')`,
  `totalLines = sum(e.linesOfCode + (e.linesRemoved ?? 0) over all events)`.
- `dayPercent = aiLines / totalLines * 100` (guard divide-by-zero).
- Render as an inline SVG polyline/path with axis labels, min 2 points; if
  only one active day exists, render a single-point chart.

## PDF content (instructor-facing, CodeVibe-branded)

1. Header — CodeVibe logo + tagline, report title.
2. Assignment identity block — assignment name, dates, student identifier
   (if entered), repo URL/commit (if set).
3. Score summary — three visual panels: AI Authorship % vs. assignment limit,
   Ownership score vs. minimum, violations count.
4. AI authorship trend line (chart).
5. Metrics table — permitted/prohibited/flagged AI lines, manual lines,
   review time, files reviewed, reviewed/unreviewed counts.
6. Violations list — each with message and occurrence count (or "None").
7. Exclusion audit summary.
8. Per-page footer — assignment id, `Page N of M`, `Generated by CodeVibe`.

## Implementation notes

- Dependency: `pdfmake` (+ font data shipped by the package). No runtime
  browser or external binary needed.
- pdfmake has no native charting; SVG is embedded via the `svg` element type.
- Generator is unit-testable and free of vscode imports where practical.
- Visual assets (logo) are resolved relative to `./resources/` via
  `context.extensionUri` if used; fallback is a text logo if unavailable.

## Testing

- Unit test: daily trend grouping (zero-day guards, midnight boundaries,
  mixed events).
- Unit test: `DocumentDefinition` builds without throwing for a representative
  report, and for an empty-metrics report.
- Unit test: generator produces a non-empty PDF buffer (pdfmake smoke test).
- Existing assignment-report JSON tests must remain untouched and green.

## Risks

- VSIX size increase ≈900KB–1.8MB (fonts). Accepted.
- If an assignment has zero events in the window, the trend renders a
  flat/empty chart with a note — no crash.
